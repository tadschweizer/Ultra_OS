## Dependency and verification

### F6/F7 repair contract - October 10

POST now requires a UUID `client_request_id` distinct from the template ID. The coach is always resolved from the signed session, never the body. Retry the same operation with the same normalized prescription: the service-role-only `create_workout_library_once` transaction returns the same template and `replayed:true`. A new intentional save uses a new key; the same coach/key with changed prescription returns 409. Keys are scoped by coach, so another coach cannot discover/replay the owner's result. Receipt intent is immutable through PATCH; DELETE leaves a receipt tombstone and replay returns 410 without resurrection.

New prerequisite migration `20261010042931_workout_library_create_idempotency.sql` adds a receipt table (RLS enabled, no anon/authenticated/public grants) and a SECURITY INVOKER transaction callable only by service_role. It retains only the canonical prescription's built-in SHA-256 fingerprint and IDs, rather than a second copy of instructions. Its unique coach/key serializes overlapping inserts; both receipt and template roll back together on failure. Apply after the metadata migration, **before** deploying the revised POST endpoint. Existing templates, IDs, library RLS and assignment field shapes are unchanged. No remote migration was applied.

The actual coach calendar supplies its signed coach profile ID only as a browser-storage namespace. An unconfirmed key and immutable payload are persisted before POST in sessionStorage, isolated by coach and tab, and restored on refresh/navigation. Unknown outcomes retain the key; retry sends the original snapshot even if editor fields changed. Confirmed success clears it, so a deliberate next create gets a fresh key. Definitive validation/access rejection or a deleted-result response permits a corrected new operation. Storage failure blocks a new request. This is refresh recovery in the same browser tab, not a server-backed cross-device editor draft.

Library read errors now show unavailable/retry state; only a successful empty GET asserts an empty library. Explicit refresh failure keeps the last loaded templates and labels them as cached. The backend assignment mapper is unaffected by this retry protocol; it still receives the real owned library row ID and the five-field metadata contract above.
