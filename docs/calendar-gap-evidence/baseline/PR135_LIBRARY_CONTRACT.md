| Library field | Type / accepted values | Legacy/default and clearing behavior |
| --- | --- | --- |
| `objective` | text or null, at most 10,000 characters | Existing rows null; explicit null clears; omission on PATCH retains |
| `coach_instructions` | text or null, at most 10,000 characters | Same; separate from description |
| `planned_if` | finite nonnegative number or null | Existing rows null; zero retained; explicit null clears |
| `target_metric` | `duration`, `distance`, `tss`, `pace`, `heart_rate`, `power`, `rpe` | Existing rows/default `duration`; explicit invalid/null rejected |
| `visibility` | `athlete_visible`, `coach_private` | Existing rows/default `athlete_visible`; explicit invalid/null rejected |

Existing fields are unchanged: `name` maps to planned `title`; sport, description, structure (including repeats/target types/ranges/**target_units**/notes), duration, canonical distance km, distance unit mi/km, planned TSS, tags, IDs and timestamps. Numeric zero is retained. Numeric empty string is normalized to null for compatibility; explicit null is not replaced by an estimate. Missing numeric planning fields may be derived from structure on POST only. PATCH omission retains stored fields. GET/POST/PATCH responses select all metadata. Library access remains coach-only and owner-scoped; template visibility governs assignment visibility, not public access to the library.

objective: libraryWorkout.objective ?? null,

Keep the existing name/title, structure, duration/distance/unit/TSS/library-ID mapping and the owner-scoped lookup. Keep explicit zero and private visibility. Keep existing planner authorization/relationship/athlete-read filtering and allow only validated planning overrides. Do not derive actual load from planned fields. The library task does not edit this handler, copy-week, loadRollups/trainingLoad, `/api/me` or calendarMutation.
